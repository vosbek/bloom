Delivery review pipeline

The agent loop runs to a done definition; evidence pins to an exact revision; a person makes one approve. This is the loop the whole product exists for.

Four lanes — reviewer, harness, control plane, evidence main path trust boundary async / pull

AGENTIC LOOP

  • The harness builds against acceptance criteria from the brief
  • The bridge serves blume_context and registers evidence tools
  • Bugs start with a failing test, then fix and rerun

EVIDENCE CONTRACT

  • Only passing runs pin evidence to the exact revision
  • Suites rerun before every review
  • Review pulls the ledger via db:conversations:listForView

ONE DECISION

  • The reviewer sees the diff, checks and screenshots
  • A single approve releases the revision
  • Lifecycle: Start → Plan → Build → Test → Review → Merge → Release → Done
